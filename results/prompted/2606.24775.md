**Curator's take**  
The paper tackles the lack of systematic, data‑management‑oriented evaluation of agent memory systems. Wei Zhou et al. decompose memory into four core modules—representation & storage, extraction, retrieval & routing, and maintenance—and benchmark 12 representative systems across five workloads, revealing that no single architecture dominates and that cost–performance trade‑offs vary widely.

**Key points**

- **Decomposition.** The authors propose a four‑module framework that splits agent memory into representation & storage, extraction, retrieval & routing, and maintenance, enabling isolated analysis of each component.

- **Benchmark breadth.** Twelve memory systems, covering streaming logs, hierarchical tiers, knowledge graphs, and hybrid architectures, are evaluated on five workloads spanning 11 datasets, providing a unified testbed for cross‑system comparison.

- **No single winner.** The study finds that effectiveness depends on how well a memory structure matches the workload bottleneck; composite hybrid systems excel in conversational QA, while graph‑based methods perform best on single‑hop factual recall but falter on temporal reasoning.

- **Fine‑grained trade‑offs.** Controlled ablations show that each module—compression, summarization, fact extraction—progressively discards information; LLM‑based extraction can improve precision but harms multi‑hop reasoning, and conservative consolidation is the safest maintenance strategy.

- **Operational costs.** Highly structured systems incur orders‑of‑magnitude higher index construction time and query latency than lightweight stores, yet do not consistently yield proportional accuracy gains.

- **Why it matters.** By treating agent memory as a data‑management system and exposing its modular trade‑offs, the work guides the design of more efficient, robust, and cost‑effective memory layers for long‑horizon LLM agents.
