**Curator's take**

Memory for LLM agents has moved beyond simple retrieval-augmented mechanisms to full data management systems that store, update, consolidate and govern information over long horizons. Existing evaluations still treat memory as a black box and benchmark it mainly with end-to-end task success metrics. Wei Zhou et al. propose a framework that splits agent memory into four core modules—representation and storage, extraction, retrieval and routing, and maintenance—and evaluate 12 representative systems across five workloads.

**Key points**

- **No single architecture dominates.** Effectiveness depends on how well the memory structure matches the workload bottleneck.
- **Retrieval accuracy drops with time.** Retrieval precision degrades significantly as the temporal distance between evidence and query increases.
- **Graph-based methods handle updates best.** They are most reliable under dynamic knowledge updates, while append-only stores struggle with targeted overwrites.
- **Append-only stores degrade over time.** Many suffer catastrophic degradation as evidence becomes more distant.
- **Structured systems cost more.** Highly structured systems incur orders-of-magnitude higher index construction time and query latency than lightweight stores, without consistent accuracy gains.
- **Why it matters.** The paper shows that memory design choices affect cost, robustness and long-horizon stability, and that no single design is best for all scenarios.
