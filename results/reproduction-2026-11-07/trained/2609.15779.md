**Curator's take**

Data agents must understand tables, files and databases that live outside the agent, but they can only see them through generic tools like SQL interfaces. Existing methods either let agents probe raw data, which scales poorly, or inject manually built semantic layers, which are costly to maintain. Meiduo Chong et al. propose EvoOntology, a self-evolving ontology layer that agents can query through tools. A builder agent builds an initial ontology, and the ontology is refined through attribution-guided edits that pass a paired evaluation.

**Key points**

- **Three layers.** The ontology has a schema layer, a content layer and a tool layer, all encapsulated as an MCP server.
- **Builder agent.** It grounds each entry in the data it probes.
- **Self-evolution loop.** Attributions find deficiencies, edits are accepted only after a paired evaluation on a held-out validation set.
- **Results.** Experiments on three data-agent benchmarks with four LLM backbones show EvoOntology consistently outperforms strong baselines and existing semantic-layer approaches.
- **Why it matters.** A self-evolving ontology bridges the agent-data gap, letting agents interact with heterogeneous data at the semantic level.
