**Curator's take**

Traditional agent development splits code across prompt templates, schemas, callbacks and workflow graphs, so learning a new framework means learning a new programming model. NVIDIA Object-Oriented Agents (NOOA) takes a simpler approach: an agent is a Python class. Its methods are the actions the model can take, fields are its state, docstrings are its prompts and type annotations are contracts. Methods with a body of ellipsis are completed at runtime by an LLM loop, while normal methods stay deterministic Python. This gives developers and agents the same interface, so agent behavior can be tested, traced and refactored like other software.

**Key points**

- **Design principles.** Where Python already has an abstraction, NOOA adopts it directly: agents are classes, capabilities are methods, type annotations are contracts, async work is asyncio, and tools and orchestration are normal Python code.
- **Six combined ideas.** NOOA is the first to combine typed input/output, pass-by-reference over live objects, code as action, programmable loop engineering, explicit object state and model-callable harness APIs for context and events on a single surface.
- **Results.** Current models use the interface effectively on SWE-bench Verified and Terminal-Bench 2.0. On ARC-AGI-3, the interface compresses a multi-agent world-model system into a single agent with a one-page skill while advancing the benchmark's score-cost Pareto frontier.
- **Why it matters.** A single Python class is both source code and prompt surface, so agent behavior can be tested, traced and optimized like other software.
