**Curator's take**

Memory for LLM agents has moved beyond simple retrieval-augmented mechanisms to a full data management system that stores, updates, consolidates and governs information over an agent's execution. Existing evaluations still treat the memory system as a black box and benchmark it mainly with end-to-end task success metrics. Wei Zhou et al. propose a framework that splits agent memory into four core modules—representation and storage, extraction, retrieval and routing, and maintenance—and evaluate 12 representative systems across five workloads and 11 datasets.

**Key points**

- **No single architecture dominates.** Effectiveness depends on how well the memory structure matches the workload bottleneck. Composite hybrid systems lead on conversational QA, while graph-based methods excel at single-hop factual recall but struggle with temporal reasoning.
- **Retrieval accuracy drops with time.** Explicit query planning and balanced hybrid search maximize relevance, but accuracy degrades significantly as the evidence becomes older.
- **Graph-based methods handle updates best.** Popular fact-extraction plugins and append-only stores struggle with targeted overwrites, and systems without lifecycle management return stale facts.
- **Append-only stores degrade over time.** Many suffer catastrophic degradation as evidence becomes more distant, and raw long-context retrieval still outperforms most memory-backed approaches for time-dependent queries.
- **Operational costs are high.** Highly structured systems incur orders-of-magnitude higher index construction time and query latency than lightweight stores, without consistent accuracy gains.
- **Why it matters.** The paper shows that memory effectiveness depends on workload fit, and that retrieval accuracy and stability drop as evidence ages. It also quantifies the cost-performance trade-offs of different memory architectures.
