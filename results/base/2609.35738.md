**Curator's take**  
The paper tackles the problem of *harness learning*: a meta‑learning framework that trains a proposer model to revise the executable harness of a language‑model agent using execution feedback. Alvin Zhang, Xuecheng Liu, Zixuan Wang, Fahim Tajwar, Daman Arora, and Ruslan Salakhutdinov propose to learn this revision policy via reinforcement learning, enabling test‑time adaptation without updating the underlying model parameters.

**Key points**

- **Problem & Approach** – Harness learning treats harness revisions as weight updates in a meta‑learning loop. A frozen solver is wrapped by a proposer that edits harness code based on task description, current harness, and an execution report. The proposer is trained with reinforcement learning, using the performance of the revised harness as reward.

- **Training & Evaluation** – The proposer is trained on Reasoning Gym and HotpotQA. On Reasoning Gym, a 4B proposer outperforms a 35B teacher in single‑step revision on task families excluded from both supervised and reinforcement learning. In multi‑hop QA, a proposer trained on HotpotQA transfers to MuSiQue and 2WikiMultihopQA, improving harnesses over successive test‑time adaptation rounds.

- **Generalization & Iteration** – Trained proposers generalize to unseen tasks and can continue improving harnesses over multiple rounds of test‑time adaptation. Even a proposer trained only on seed‑harness inputs can improve revised harnesses, indicating robustness across adaptation contexts.

- **Why it matters** – Harness learning offers a path toward continually learning agents that convert accumulated execution experience into generalizable harness improvements, enabling better model‑tool orchestration without costly parameter updates.
